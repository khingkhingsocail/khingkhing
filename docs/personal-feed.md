# สำหรับคุณ — ฟีดสไลด์และแนะนำรายบุคคล

หน้าสำหรับคุณแสดงรูปภาพและวิดีโอแบบเต็มพื้นที่ฟีด ปัดขึ้นเพื่อดูโพสต์ถัดไป ปัดลงเพื่อย้อนกลับ หรือใช้ปุ่มลูกศรบนหน้าและ ArrowUp/ArrowDown เมื่อโฟกัสพื้นที่ฟีด ปัดแนวตั้งอย่างน้อย 45 px และมากกว่าการลากแนวนอน 1.25 เท่าจึงเปลี่ยนโพสต์; trackpad/wheel ใช้ scroll snap เดิม ไม่มี autoplay ข้ามโพสต์ให้เอง วิดีโอเล่นเมื่อเห็นอย่างน้อย 60% ในพื้นที่ฟีด และหยุดเมื่อเปิด Comments/โปรไฟล์/Arena หรือซ่อนแท็บ

## ความชอบของแต่ละบุคคล

ระบบใช้กติกาจัดอันดับแบบโปร่งใส ไม่ได้เรียกโมเดล AI หรืออ้างว่าทัดเทียมระบบ TikTok ระดับโลก ความชอบมีเฉพาะชนิดรูป/วิดีโอ หัวข้อจากคำสำคัญและ hashtag ในชื่อ/คำอธิบาย และรหัสครีเอเตอร์สาธารณะ ไม่วิเคราะห์เพศ อายุ สุขภาพ หรือข้อมูลส่วนตัวในภาพ

| สัญญาณ | น้ำหนักตั้งต้น |
|---|---:|
| กดใจ / ยกเลิกใจ | +5 / −5 |
| บันทึก / เอาออกจากบันทึก | +7 / −7 |
| เห็นภาพที่โหลดแล้วหรือวิดีโอเล่นจริงต่อเนื่อง 8 วินาที | +1 |
| เลื่อนผ่านภายใน 0.2–2 วินาทีที่สื่อพร้อม | −1 |
| ไม่สนใจ | −6 และซ่อนโพสต์นั้นในการจัดคำแนะนำครั้งถัดไป |

น้ำหนักแต่ละคุณลักษณะจำกัด −20 ถึง +20 และลดค่าก่อนเพิ่มสัญญาณใหม่เล็กน้อย เก็บสูงสุด 300 คุณลักษณะและ 200 โพสต์ไม่สนใจ คะแนนยังรวมความสดใหม่และยอดวิวที่มีจริงในสัดส่วนจำกัด; ชนิดสื่อมีน้ำหนักน้อยกว่าหัวข้อ/ครีเอเตอร์ แทรกการสำรวจรายการใหม่ทุกห้าตำแหน่ง และพยายามไม่ให้ครีเอเตอร์เดียวกันติดกันเกินสองโพสต์เมื่อมีทางเลือก

การจัดอันดับใช้เฉพาะ **โพสต์สาธารณะในชุดที่โหลด** ไม่ใช่ทุกโพสต์ทั้งระบบ รูป/วิดีโอส่วนตัวและตัวอย่างไม่ส่งสัญญาณไป server ลำดับที่เห็นไม่เปลี่ยนทันทีหลังไลค์หรือดูนาน เพื่อไม่ให้หน้ากระโดด; กดรีเฟรชเพื่อจัดใหม่ ส่วนหน้าถัดไปที่โหลดใช้ความชอบล่าสุด ผู้เริ่มใช้ยังไม่มีสัญญาณจะเห็นรายการใหม่ทั่วไป

## การซิงค์และความเป็นส่วนตัว

ผู้เข้าสู่ระบบใช้บัญชีที่ server ตรวจ session แล้วเป็นเจ้าของความชอบใน Managed Database และอ่านได้เมื่อเข้าสู่บัญชีเดิมอีกอุปกรณ์ ผู้เยี่ยมชมเก็บความชอบเฉพาะเบราว์เซอร์; ถ้า localStorage ใช้ไม่ได้ จะใช้เฉพาะแท็บนั้น ไม่มีการ fingerprint ผู้เยี่ยมชม หรือย้ายความชอบ guest ไปบัญชีอัตโนมัติ

ปุ่ม “ปรับตามความชอบ: ปิด” หยุดเก็บสัญญาณใหม่และใช้ลำดับโพสต์ล่าสุด โดยไม่ลบข้อมูลเดิม การตั้งค่าปิดนี้เป็นรายบัญชีบนเบราว์เซอร์นั้น ไม่ใช่การตั้งค่าซิงค์ข้ามอุปกรณ์ ป้ายสถานะแจ้งเมื่อข้อมูลยังไม่ซิงค์ กดลองใหม่จะใช้ UUID เดิม ไม่เพิ่มสัญญาณซ้ำหลังคำตอบสูญหาย สัญญาณที่ยังส่งไม่สำเร็จอยู่ในหน่วยความจำเท่านั้น ออกจากหน้า/ปิดแท็บอาจทำให้คิวค้างสูญหาย แต่ข้อมูลที่ server บันทึกแล้วคงอยู่

Like/save ในส่วนนี้เป็นสัญญาณส่วนบุคคล ไม่ได้เปลี่ยนเป็นจำนวนไลค์สาธารณะหรือระบบ bookmark บัญชีเต็มรูปแบบ API ไม่รับ userId หรือหัวข้อความชอบจากผู้ส่ง ใช้ข้อมูลโพสต์จริงใน server; payload และข้อมูลความชอบไม่ถูกบันทึกใน debug network logs

## โครงสร้าง

`shared/feedPersonalization.ts` เป็น contract และ pure ranker, `server/feed-personalization/` เป็น API ที่ล็อกบัญชี/ข้อมูลความชอบก่อนเขียนและตรวจ UUID ซ้ำ, `client/src/hooks/usePersonalFeed.ts` จัดคิวกับข้อมูลบัญชี/guest, `useFeedBehavior.ts` วัดการดูที่มีสิทธิ์, `useFeedSwipe.ts` จัด gesture และการเปลี่ยนทีละโพสต์ ฟีดเดิมยังใช้ยอดวิวและระบบอัปโหลด/Comments/โปรไฟล์ร่วมเดิม ไม่ย้ายข้อมูลไฟล์เก่า

## อายุข้อมูลและข้อจำกัดที่ทราบ

ความชอบบัญชีและ event log ไม่มีงานล้างอัตโนมัติตามอายุในรุ่นนี้ จึงคงอยู่ในฐานข้อมูลจนกว่าจะมีการลบบัญชี; event ของโพสต์ที่ถูกลบจะถูกลบตาม foreign key ส่วนคะแนนความชอบสรุปไม่ย้อนคืนตามการลบโพสต์ ไม่ได้อ้างว่าข้อมูลถูกล้างหลัง 30 วัน

เมื่อเปลี่ยนบัญชี Home สร้างฟีดใหม่ และมี guard แสดงลำดับสาธารณะที่เป็นกลางระหว่างยังโหลดความชอบ ไม่อ่าน ref ของบัญชีก่อนหน้ามาจัดหน้าที่กำลังโหลด ถ้าเบราว์เซอร์ไม่รองรับ IntersectionObserver ระบบไม่เดาว่าทุกโพสต์มองเห็น: ไม่ autoplay และไม่เก็บ watch/skip หรือยอดวิวโดยการเดา

การทดสอบ UI ใช้ SSR, pure selectors และ effect harness; API ใช้ auth/DB mocks ไม่ใช่การเข้าสู่ระบบจริงหรือ browser gesture integration ตาราง/index และประวัติ migration ตรวจจากฐานข้อมูลจริงแบบอ่านอย่างเดียว ไม่มีโพสต์หรือสัญญาณทดสอบถูกเพิ่มลงฐานข้อมูลที่ใช้ร่วมกับเว็บไซต์
