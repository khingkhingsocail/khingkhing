# โปรไฟล์บัญชีและแจ้งเตือน — ขิงขิง

## การใช้งาน

เข้าสู่ระบบขิงขิง แล้วเปิด **โปรไฟล์ → ตั้งค่าโปรไฟล์/แก้ไขโปรไฟล์** สามารถบันทึกชื่อที่แสดง ชื่อผู้ใช้ แนะนำตัว หมวดหมู่ สถานที่ เว็บไซต์ รูปโปรไฟล์และรูปปกลง Managed MySQL ได้ รูปใช้ JPG, PNG หรือ WebP ไม่เกิน 5 MiB ต่อไฟล์ การแก้ไขรูปใหม่ย่อรูปในเครื่องก่อนส่งและตรวจการถอดรหัสที่เซิร์ฟเวอร์ เปิดบนอุปกรณ์อื่นด้วยบัญชีเดิมเพื่อโหลดข้อมูลชุดเดียวกัน

ข้อมูลบัญชีชุดนี้ยังเป็นส่วนตัว ไม่ได้เปิดเผยให้ผู้เข้าชมคนอื่นโดยอัตโนมัติ และชื่อผู้ใช้เป็นชื่อแสดง ไม่ใช่การจองชื่อเฉพาะทั่วระบบ ผู้เยี่ยมชมยังใช้โปรไฟล์ใน IndexedDB เดิม การเข้าสู่ระบบไม่ย้ายโปรไฟล์หรือรูปเก่าขึ้นเซิร์ฟเวอร์ หากต้องการย้าย ให้เลือก **นำเข้าจากเบราว์เซอร์นี้** เพื่อใส่ข้อมูลลงแบบร่าง แล้วกด **บันทึกโปรไฟล์** ด้วยตนเอง คลังไฟล์ส่วนตัวเดิมยังอยู่เฉพาะเบราว์เซอร์ ไม่ได้ซิงค์หรือเปิดเป็นสาธารณะ

โพสต์สาธารณะใหม่ที่ส่งขณะเข้าสู่ระบบจะผูกเจ้าของกับบัญชีที่เซิร์ฟเวอร์ตรวจแล้ว สำหรับโพสต์ anonymous เดิม ให้เข้าสู่ระบบบนเบราว์เซอร์ที่มีรหัสเจ้าของโพสต์ เปิด **โพสต์สาธารณะ** แล้วกด **ผูกโพสต์กับบัญชีเพื่อรับแจ้งเตือน** ไม่สามารถผูกโพสต์ของบัญชีอื่นหรือเดาเจ้าของจากชื่อ/อีเมลได้ หลังผูกแล้วบัญชีเดิมลบโพสต์ได้จากอุปกรณ์อื่น ขณะนี้ไม่มีการสร้างแจ้งเตือนย้อนหลังสำหรับความคิดเห็นก่อนผูกเจ้าของ

## แจ้งเตือนความคิดเห็นและคำตอบ

กระดิ่งอยู่ด้านบนขวาของแอป เมื่อคนอื่นแสดงความคิดเห็นหรือส่งคำตอบ ระบบสร้างแจ้งเตือนให้เจ้าของโพสต์และเจ้าของข้อความที่ถูกตอบ ถ้าเป็นคนเดียวกันจะมีหนึ่งรายการ ไม่แจ้งตนเองและการลองส่ง UUID เดิมไม่สร้างแจ้งเตือนซ้ำ กดรายการเพื่อทำเครื่องหมายอ่านและเปิดโพสต์พร้อมเธรดความคิดเห็นต้นทาง มีโหลดรายการก่อนหน้าและอ่านทั้งหมดถึงขอบเขตรายการที่ระบบโหลดแล้ว สถานะอ่านบันทึกในฐานข้อมูลและใช้ร่วมกันทุกอุปกรณ์ของบัญชีเดียวกัน

อัปเดตในแอปทุก 15 วินาทีขณะหน้าเว็บเปิดและมองเห็น ไม่ใช่ push notification, อีเมล หรือแจ้งเตือนขณะปิดเบราว์เซอร์ รายการของข้อความที่ลบแล้วไม่ถูกส่งออกจาก API และโพสต์ที่ถูกลบจะลบแจ้งเตือนตาม foreign key

## โครงสร้างและสิทธิ์

| ส่วน | การจัดเก็บและสิทธิ์ |
| --- | --- |
| `user_profiles` | หนึ่งแถวต่อบัญชี พร้อมรูป BLOB และ revision; API ใช้ผู้ใช้จาก session เท่านั้น |
| `public_media.owner_user_id` | nullable เพื่อรักษา anonymous เดิม; ผูกใหม่ภายใต้ row lock ด้วยรหัสเจ้าของเดิม |
| `user_notifications` | ผู้รับ ผู้กระทำ comment/media/root และ readAt; unique `(comment_id,recipient_id)` |
| `/api/profile/me` | GET/PUT และรูป `/avatar`, `/cover`; session + header, private/no-store |
| `/api/notifications` | GET cursor และ unread/watermark; session ผู้รับเท่านั้น |
| `/api/notifications/:id/read` | ทำเครื่องหมายเฉพาะรายการของผู้รับ; session + custom header |
| `/api/notifications/read-all` | ทำเครื่องหมายเฉพาะผู้รับและลำดับถึง throughId |
| `/api/media/:id/claim` | session + header + token เดิม; ไม่เปิดเผย token/hash ใน metadata |

ความคิดเห็นและแจ้งเตือนถูกเขียนใน transaction เดียวกัน การบันทึกโปรไฟล์ล็อกบัญชีก่อนและตรวจ revision เพื่อปฏิเสธการเขียนทับจากอุปกรณ์อื่นด้วย 409 ไม่ fallback ไป IndexedDB แล้วอ้างว่าสำเร็จ รูปเดิมถูกเก็บไว้เมื่อแก้เฉพาะข้อความ การแสดงข้อมูลส่วนตัวถูกกันออกจากตัวเก็บ debug interaction/network

## สถานะตรวจสอบ

เพิ่ม migration `0008_loose_sugar_man.sql` แบบ additive และตรวจว่าตาราง/คอลัมน์อยู่ใน Managed MySQL จริง ไม่ลบข้อมูลเดิม ทดสอบ browser ปุ่มบันทึก local ด้วยค่าเดิมสำเร็จและตรวจสถานะ guest กระดิ่ง/API ส่วนตัวปฏิเสธ 401 การเขียนโปรไฟล์บัญชีและเหตุการณ์จากคนละบัญชีตรวจด้วย integration tests ที่ mock session/ฐานข้อมูลแยกจากผู้ใช้จริง ไม่สร้างบัญชีปลอมใน Preview และไม่เขียนความคิดเห็นทดสอบเป็นสาธารณะ การทดสอบด้วยสองอุปกรณ์และบัญชีผู้ใช้จริงยังต้องเข้าสู่ระบบด้วยบัญชีที่ผู้ใช้เลือก

ชุดตรวจสุดท้าย: `pnpm check` ผ่าน, `pnpm test` ผ่าน 40 ไฟล์/250 tests และ production build ผ่าน มี regression ป้องกันชื่อบัญชีส่วนตัวถูกนำไปใช้เป็นชื่อคอมเมนต์สาธารณะ ผลบันทึกโปรไฟล์คืน metadata และ revision จาก transaction เดียวกัน ไม่เสี่ยงอ่านข้อมูลเวอร์ชันใหม่ปนกับภาพแบบร่างเก่า.
